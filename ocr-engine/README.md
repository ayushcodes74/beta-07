# TrustGrade OCR Engine

This repository hosts the modular OCR Engine for **TrustGrade**, an AI-assisted assignment evaluation platform.

---

## Architecture Overview

1. **Module 1: PDF Ingestion & Processing** (`app/ingestion/`) — Safely validates PDFs and rasterizes pages to PNGs.
2. **Module 2: Image Preprocessing & Enhancement** (`app/preprocessing/`) — Improves image quality, corrects orientation/skew, denoises, and normalizes illumination while strictly preserving handwriting details.
3. **Module 3: Text & Handwriting Recognition** (`app/recognition/`) — Recognizes printed and handwritten text from preprocessed pages.
4. **Module 4: Mathematical Recognition & Quality Analysis** — Recognizes math expressions and computes OCR confidence.
5. **Module 5: OCR API & Integration** — Assembles the complete REST API and Supabase storage pipeline.

## Module 2: Image Preprocessing & Enhancement

### 1. Purpose & Principles
Module 2 receives individual page images generated by Module 1 and prepares them for optimal OCR recognition.

> **Core Principle: Improve the image, never invent or destroy the student's written answer.**

#### Handwriting & Math Preservation Rules:
- **Never aggressively smooth handwriting:** Protects cursive pen loops and thin strokes.
- **Preserve fine details:** Decimal points, punctuation, subscripts, superscripts, and math operators ($\Sigma, \int, \delta, \sqrt{}$) remain sharp.
- **Continuous tones retained:** The primary enhanced image maintains full color/tonal depth rather than harsh black/white thresholding.
- **Original image immutability:** The original input image is strictly preserved; enhanced and variant images are saved in separate subfolders.

---

### 2. Directory Structure & Output Artifacts

Given `submission_id="submission-123"` and `output_dir="processed"`:

```text
processed/
└── submission-123/

    │   ├── page_001.png
    │   └── page_002.png
    ├── enhanced/                   # Default high-quality enhanced images for Module 3
    │   ├── page_001.png
    │   └── page_002.png
    └── variants/                   # Optional specialized variants
        ├── page_001_gray.png       # 8-bit grayscale variant
        └── page_001_threshold.png  # Adaptive binary thresholded variant
```

### 5. Configurable Options (`PreprocessingConfig`)

| Option | Type | Default | Purpose |
|---|---|---|---|
| `enable_orientation_correction` | `bool` | `True` | Detect and apply 90/180/270 deg rotation |
| `enable_deskew` | `bool` | `True` | Detect and correct small text tilt angles |
| `max_deskew_angle` | `float` | `15.0` | Maximum allowable deskew rotation angle in degrees |
| `deskew_min_angle` | `float` | `0.5` | Threshold below which rotation is skipped to avoid interpolation blur |
| `enable_denoising` | `bool` | `True` | Gentle edge-preserving bilateral filtering |
| `bilateral_d` | `int` | `5` | Pixel neighborhood diameter for bilateral filter |
| `bilateral_sigma_color` | `float` | `30.0` | Radiometric filter sigma |
| `enable_contrast_enhancement` | `bool` | `True` | Background normalization and CLAHE |
| `clahe_clip_limit` | `float` | `2.0` | Threshold for contrast limiting in CLAHE |
| `generate_grayscale` | `bool` | `True` | Output an 8-bit grayscale variant |
| `generate_thresholded` | `bool` | `True` | Output an adaptive/Otsu thresholded binary variant |
| `thresholding_method` | `str` | `"adaptive"` | Binarization algorithm (`"adaptive"` or `"otsu"`) |
| `min_ocr_width` | `int` | `600` | Width threshold for low-resolution warning |
| `min_ocr_height` | `int` | `800` | Height threshold for low-resolution warning |
| `blur_threshold` | `float` | `80.0` | Laplacian variance threshold for blur detection |
| `blank_std_threshold` | `float` | `8.0` | Intensity std dev below which page is marked blank |

---

### 6. Error Handling & Custom Exceptions

All module exceptions inherit from `PreprocessingError`:
- `InvalidImageError`: Corrupted, empty, or unreadable image file.
- `UnsupportedImageFormatError`: File format not PNG or JPEG.
- `ImageLoadError`: Failed to decode image bytes into memory.
- `ImageProcessingError`: Transformation failure during pipeline execution.
- `ImageSaveError`: Failed to encode or save output image to disk.

#### Fault Isolation & Cleanup:
- Each page is preprocessed in isolation; a corrupted page in a batch does not corrupt or cancel other valid pages.
- If processing fails mid-page, any partial files for that page are removed while preserving the original input image.

---

### 7. Handoff & Integration for Module 3 (Text Recognition)

1. **Default Image Variant:** Module 3 should consume `enhanced_image_path`. This file has undergone illumination flattening, deskewing, and edge-preserving noise suppression while retaining continuous color tones.
2. **Binary/Grayscale Fallbacks:** If a specialized OCR model (e.g., traditional CRNN or legacy Tesseract) requires binarized or single-channel inputs, it can consume `variants.grayscale` or `variants.thresholded`.
3. **Original Fallback:** If `image_quality.needs_review` is `True` or if confidence scores in Module 3 indicate potential information loss, Module 3 can inspect `original_image_path`.
4. **Orientation & Skew Diagnostics:** The applied corrections and any warnings are reported in `image_quality`, enabling Module 3 to assess image readability context.

## Module 3: Text & Handwriting Recognition

### 1. Purpose & Core Principles
Module 3 processes enhanced page images from Module 2, identifies text regions, classifies them as printed or handwritten, reconstructs the original human reading order (including multi-column layouts), and extracts structured text blocks with calibrated confidence scores.

> **Core Principle: Transcribe what the student wrote. Never improve, rewrite, guess, or grade the student's answer.**

---

### 2. Model Evaluation & Architecture

#### Engines:
0. **OCR.space Engine 3 (default, `backend="ocrspace"`):**
   - Cloud OCR with strong handwriting recognition ([OCR.space API](https://ocr.space/ocrapi), `OCREngine=3`). Each page image is JPEG-compressed under 1 MB and sent separately; word boxes are mapped back to page coordinates. Student pages leave this machine when it is enabled.
   - Configure in `ocr-engine/.env` (gitignored): `OCR_SPACE_API_KEY=<your key>`; optional `OCR_SPACE_ENGINE` (default 3), `OCR_SPACE_ENDPOINT` (PRO plans use another host), `OCR_SPACE_MAX_UPLOAD_BYTES` (default 1000000). Restart the service after changing it.
   - Free plan limits: 1000 Engine 3 conversions/month (one per page), 500 requests/day/IP, 1 MB per file.
   - OCR.space returns no confidence scores, so its blocks have `confidence: null`.
   - **Fallback:** with no key, or when a request fails, the page is recognized by local PaddleOCR and the page gets an `"OCR.space unavailable (...)"` warning. Key/quota errors (HTTP 401/403/429, "limit exceeded") pause OCR.space for 10 minutes. `/health` reports `ocr_space_engine` as `loaded`, `unavailable` (no key) or `disabled`.
1. **PaddleOCR 3.x (local, `backend="paddleocr"`; also the OCR.space fallback):**
   - PaddleOCR detects **and** recognizes every text line on the full page (printed and handwritten), using `PP-OCRv6_small_det` + `PP-OCRv6_small_rec` by default (~10 s/page on CPU). Set `paddle_det_model_name` / `paddle_rec_model_name` in `RecognitionConfig` to `PP-OCRv6_medium_*` for higher recall (~4x slower) or `PP-OCRv6_tiny_*` for speed.
   - Word fragments are merged into visual lines; a line is split into separate blocks where the horizontal gap exceeds `line_merge_gap_factor` x line height (side-by-side working columns). `full_text` keeps one visual row per line.
   - Models are downloaded on first use to `~/.paddlex/official_models` and preloaded in a background thread when the API starts (`OCR_PRELOAD_MODELS=false` disables this).
   - *Windows note:* oneDNN/MKLDNN is disabled by default (`paddle_enable_mkldnn=False`); PaddlePaddle 3.x crashes in oneDNN on Windows CPU (`ConvertPirAttribute2RuntimeAttribute not support`).
   - Legacy PaddleOCR 2.x installs are still supported via the old `ocr()` API.
   - **Job persistence:** each job workspace lives in `ocr-engine/storage/<job_id>/` (override with `OCR_STORAGE_ROOT`) and holds `submission.pdf`, `job.json` and, once finished, `result.json`. After a service restart, finished jobs are restored from disk on first lookup; jobs that never finished are re-run from their saved PDF. Service shutdown no longer deletes workspaces.
2. **TrOCR (`microsoft/trocr-small-handwritten`, opt-in `backend="auto"` or `"trocr"`):**
   - Legacy hybrid path: OpenCV region detection, TrOCR for handwritten crops, PaddleOCR for printed crops. Not loaded under the default backend.
3. **Resilient CPU Fallback Engine:**
   - Built-in structural analysis engine utilizing OpenCV morphological connected components, stroke direction variance, and distance transforms.
   - Operates with sub-15ms per-page latency on standard CPUs without GPU or external internet downloads.
   - Guarantees deterministic, honest confidence scores without hallucinating text.

### 3. Usage & Service Interface

Module 3 provides reusable Python interfaces for single-page and multi-page batch recognition without HTTP overhead:

```python
from app.recognition import recognize_page, recognize_pages, PageRecognitionResult

# 1. Single Page Recognition
result: PageRecognitionResult = recognize_page(
    image_path="processed/sub-123/enhanced/page_001.png",
    submission_id="sub-123",
    page_number=1,
)

print("Status:", result.status)
print("Full Text:\n", result.full_text)
for block in result.text_blocks:
    print(f"[{block.sequence}] ({block.type}, conf={block.confidence}): {block.text}")

# 2. Multi-page Batch Recognition
results = recognize_pages(
    pages=[
        "processed/sub-123/enhanced/page_001.png",
        "processed/sub-123/enhanced/page_002.png",
    ],
    submission_id="sub-123",
)
```

### 5. Reading Order & Multi-Column Support

`ReadingOrderReconstructor` analyzes spatial page geometry:
- **Spanning Headers:** Full-width question titles across the page are placed first in the sequence.
- **Multi-Column Flow:** Left columns are completely read top-to-bottom before proceeding to the right column, preventing column interleaving.
- **Horizontal Banding:** Left-to-right alignment is preserved within the same vertical band.

---

### 6. Mathematical Content Handling & Module 4 Integration

- **Detection:** Regions exhibiting mathematical syntax ($=, +, -, /, *, \int, \sum, \sqrt{}, x_1$) or sub/superscript geometry are identified.
- **Preservation:** Bounding boxes and regional context are preserved without hallucinating ordinary words over formulas.
- **Warnings:** Flagged with `"Mathematical notation detected; bounding box preserved for specialized Module 4 processing."`.
- **Handoff:** Module 4 can directly inspect `block.bounding_box` and the original or enhanced page image to perform formula parsing and LaTeX translation.
